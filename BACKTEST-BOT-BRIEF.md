Читать целиком перед первой строкой кода. Почти каждый пункт в разделе «Грабли» стоил
нескольких часов и одной испорченной записи в реальном журнале.

## 1. Что уже работает (боевой бот)

Телеграм-бот ведёт журнал **реальных** сделок в Google-таблице. Пользователь кидает одну
ссылку на снимок входа из TradingView, бот сам дозабирает остальные таймфреймы с его
графика, задаёт несколько вопросов и пишет строку в журнал. При закрытии спрашивает суммы
по каждому пропу, сам снимает скрины закрытия и считает статистику.

**Бот:** `@tradeleonov_bot` (в Telegram называется «trade»).

### Диалог открытия

1. Пользователь присылает ссылку `https://www.tradingview.com/x/<id>/` (одну).
2. Бот вытаскивает из неё символ и **сразу** запускает съёмку остальных таймфреймов
   в фоне — она идёт параллельно вопросам, поэтому не тратит время пользователя.
3. Вопросы по очереди: мысли до входа → сессия (определяется сама, кнопкой можно
   переопределить) → Long/Short → на каких пропах → риск в долларах по каждому →
   оценка позиции (A / A (-) / B / C).
4. Запись в таблицу, ответ вида «✅ USDCHF Short · оценка B · 100k challenge — 450$ (0.45%)»
   и дальше обязательная фраза:
   `Записал.` / **`Ты дал цену слова, у тебя есть 5 минут…`** (жирным) / `/closetrade для закрытия`.

Если ссылок несколько — старый ручной путь, актив спрашивается кнопками.

### Диалог закрытия (`/closetrade`)

Выбор сделки → бот сам снимает скрины 5м и 1ч (без DXY) → сумма в долларах по каждому
пропу → «Ошибки после сделки/выводы:» → запись, пересчёт процентов и RR.

### Команды

`/stats`, `/balance`, `/closetrade`, `/tv` (состояние съёмщика), `/shots <ссылка>`
(дослать скрины в последнюю строку), `/reset`.

## 3. Что делать по-другому для бектестов

Задача пользователя: **тот же журнал, но для бектестов на FX Replay** (бесплатная версия).

### Главное отличие

**Скрины он будет делать сам.** FX Replay — не TradingView, там нет ссылок вида `/x/<id>/`,
и всей машинерии с `tv-browser` / `tv-worker` для нового бота **не нужно**. Это убирает
самую хрупкую половину системы. Бот просто принимает картинки или ссылки, которые пришлёт
пользователь, и складывает их в таблицу.

Это стоит подтвердить у него в начале: сколько скринов на сделку он хочет прикладывать
и в каком виде (файлом в Telegram или ссылкой).

### Что нужно решить до кода

Задать пользователю, потому что от ответов зависит структура таблицы:

1. **Отдельная таблица или лист в этой?** Рекомендация — отдельная таблица: бектестов
   будет в разы больше, чем реальных сделок, и они не должны попадать в боевую статистику.
2. **Отдельный бот в Telegram или команда в текущем?** Рекомендация — **отдельный бот**
   (новый токен у @BotFather). Иначе одна опечатка в режиме — и бектест уедет в реальный
   журнал. Два бота = два разных чата, перепутать физически нельзя.
3. **Что считать в статистике.** У бектестов нет пропов и долларов — есть серия сделок по
   стратегии. Логичнее: винрейт, средний RR, количество по сессиям, по парам, по оценкам.
   Это другой лист `Статистика`, не копия боевого.
4. **Короче диалог.** За вечер бектестов сделок десятки. Семь вопросов на каждую он бросит
   через полчаса. Разумный минимум: пара → Long/Short → RR или результат → мысли/выводы →
   скрин. Остальное — опционально, кнопкой «подробнее».

### Что переиспользовать почти без изменений

- Каркас `bot.js`: Telegraf, машина состояний, сохранение диалога на диск.
- `sheetsPost` со всей обвязкой вокруг Apps Script (echo-редирект, `requestId`).
- Определение сессии по времени (`detectSession`) — для бектестов тоже полезно.
- Способ тестировать диалог фейковыми апдейтами (см. ниже).
- Юнит systemd и способ деплоя.

## 4. Грабли. Каждая стоила времени

### Telegram / Telegraf

- **`handlerTimeout` по умолчанию 90 секунд.** Длинный обработчик отваливается с «Promise
  timed out», и в режиме polling это роняет сам опрос — бот молча глохнет. Ставить
  `new Telegraf(token, { handlerTimeout: 600000 })`.
- **Если опрос упал, процесс обязан умереть** (`process.exit(1)` в `bot.launch().catch`).
  Express держит порт, systemd считает службу живой, а бот молчит.
- **Нельзя дёргать `getUpdates` через curl для проверки живости** — Telegram разорвёт
  опрос самого бота. Живость проверять по логам и реальным сообщением в чат.
- **Состояние диалога обязано переживать перезапуск.** Пользователь однажды вводил сумму
  закрытия ровно в момент деплоя — диалог потерялся, сделка не записалась. Состояние
  пишется в `state.json` на каждом шаге.
- Вебхук и polling одновременно не работают: Telegram отдаёт апдейты либо туда, либо сюда.

### Google Apps Script

- **`setFormula` подставляет формулы в локали таблицы.** В ru_RU разделитель `;`, а
  `=SUM(1,2)` даст `1.2`. В `Code.gs` это делает обёртка `loc()`.
- **Ответ на POST — редирект на `script.googleusercontent.com/…/echo`**, а содержимое там
  появляется с задержкой: первый GET нередко отдаёт 404. Скрипт при этом **уже отработал**.
  Поэтому: POST без редиректа → GET по `Location` с повторами → повторный POST только с тем
  же `requestId` (скрипт кэширует ответ в `CacheService`, дублей не будет).
  **Curl-ом это тестировать нельзя** — теряет тело на редиректе.
- **Скорость ответа скачет:** замеры 5 / 8 / 31 / 45 секунд. Это свойство связки, а не сети.
  Минутная задержка `/stats` — не поломка.
- Сразу после «Новая версия» 10–20 секунд запросы могут отдавать 404 или HTML.
- `appendRow` парсит текст (дата «1-5» станет 1 мая), `setValue` — нет.
- Серийное значение даты считается в **текущем** поясе таблицы. Менять пояс и писать данные
  в одном батче нельзя — даты сдвинутся. Сначала пояс, потом запись.

### Сервер

- **Выход из SSH убивал Chromium.** Snap запускает браузер в пользовательском сеансе, а не
  в cgroup службы; без lingering `systemd-logind` гасит сеанс вместе с браузером.
  Лечится раз и навсегда: `sudo loginctl enable-linger ubuntu`.
- **Брошенные CDP-подключения копятся.** `connectOverCDP` звался на каждую задачу, а закрыть
  подключение нечем: `browser.close()` на CDP **убивает сам браузер**. За двое суток набралось
  1222 живых соединения, съёмка расползлась с 84 секунд до 931, потом браузер перестал
  принимать новые подключения. Лечение — одно подключение на процесс, переиспользуется.
- **Обновления snap прилетают без спроса.** Окно сдвинуто на ночь воскресенья:
  `snap set system refresh.timer=sun,01:00-02:00`.
- **Ежедневный `apt-daily-upgrade`** в 06:35 UTC перезапускал службы посреди съёмки.
  Перенесён на 01:00 UTC, `needrestart` переведён в режим `l`.
- Жёсткая зависимость `Requires=` роняет зависимую службу вместе с основной. Нужен `Wants=`.
- **Долгие SSH-команды с Mac рвутся** (`curl` на 85-секундную съёмку возвращал пустоту,
  exit 137). Запускать через `nohup bash -c "... > /tmp/out.json" &` и забирать файл отдельно.

### Тестирование

- **Гонять диалог целиком без Telegram:** подменить `require('telegraf').Telegram.prototype.callApi`
  (именно прототип — `handleUpdate` создаёт новый `Telegram` на каждый апдейт) и слать фейковые
  апдейты в `bot.handleUpdate`.
- **Команды в тестах нужно слать с `entities: [{ type: 'bot_command' }]`**, иначе Telegraf их
  не видит и отвечает «Не понял».
- `bot.js` экспортирует функции и поднимает сервер только при прямом запуске — тесты делаются
  через `require('./bot.js')`.
- **Тестовые строки надо уметь удалять по маркеру.** Пара берётся из реальных данных и не может
  быть `TEST-…`, поэтому `deleteTestRow` принимает `{ row, match }` и сверяет маркер с колонкой E.
  Без этого тестовая сделка остаётся в журнале как открытая.

## 5. Как работать с этим пользователем

- Он **не программист**. Вопросы «закоммитить?» для него шум — он не может оценить
  последствия. Принимай технические решения сам и объясняй одной-двумя строчками.
- **Рабочее сразу в git.** Иначе код на сервере и в репозитории расходятся, и через месяц
  выводы делаются по несуществующему коду.
- **Пошаговые инструкции для него писать предельно конкретно** — куда нажать, что вставить.
  Он работает по ним буквально.
- Он торгует в реальном времени. **Перезапуск бота посреди его сделки ломает ему запись** —
  проверять, что диалог не в середине, или предупреждать.
- Говорить прямо, если он не прав. Один раунд возражений — норма; настаивает — делать как он.
